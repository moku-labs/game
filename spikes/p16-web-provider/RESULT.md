# P16: web provider for the `platform` plugin

**Goal: know what mobile browsers give for haptics, keep-awake, orientation lock, Back, lifecycle and WebGPU in October 2026, and what the web provider returns when a capability is missing.**

Status: done from documents only. Nothing was run on a device. Support data is MDN browser-compat-data 8.1.4, built 2026-10-01 ([data.json](https://unpkg.com/@mdn/browser-compat-data@8.1.4/data.json)). "BCD" below means that file. Claims marked "not verified" have no primary source or no device test.

## WebGPU

| target | status | condition | source URL |
|---|---|---|---|
| iOS Safari 26 | On by default since 26.0. Also iPadOS, macOS 26, visionOS. | Device list not verified. | https://webkit.org/blog/16993/news-from-wwdc25-web-technology-coming-this-fall-in-safari-26-beta/ , https://webkit.org/blog/17333/webkit-features-in-safari-26-0/ , https://github.com/gpuweb/gpuweb/wiki/Implementation-Status |
| WKWebView iOS 26 (Tauri iOS) | On, because WebGPU is on by default in iOS 26. An Apple engineer: Safari feature flags "only impact Safari and not WebKit generally"; WKWebView gets the feature when it is on by default. BCD: `webview_ios` 26. | iOS 26 or later. On iOS 18 and older: no WebGPU, WebGL only. Not verified on device. | https://developer.apple.com/forums/thread/770862 , https://github.com/mdn/browser-compat-data/blob/main/api/GPU.json |
| Chrome Android | On by default since 121. | Android 12+ with Qualcomm (Adreno) or ARM (Mali) GPU. Imagination GPUs since 139 on Android 16+. Samsung Xclipse: still in progress. Android 11 and older: no. | https://developer.chrome.com/blog/new-in-webgpu-121 , https://groups.google.com/a/chromium.org/g/blink-dev/c/YFWuDlCKTP4 , https://github.com/gpuweb/gpuweb/wiki/Implementation-Status |
| Samsung Internet | BCD: since 25.0. | Same GPU and OS gate as Chrome. Not verified. | https://github.com/mdn/browser-compat-data/blob/main/api/GPU.json |
| Android WebView (Tauri Android) | Sources disagree. BCD: 121, same as Chrome. A blink-dev intent of 30 May 2024 says WebGPU is "already" on Android WebView. chromestatus has an empty WebView field. caniwebview.com says no. Treat as on when Chrome 121+ WebView, Android 12+, Adreno or Mali. Not verified on device. | WebView version follows the Play Store update, not the app. | https://groups.google.com/a/chromium.org/g/blink-dev/c/eZqMmX7q_bA/m/euMLVMpxAgAJ , https://chromestatus.com/feature/5119617865613312 , https://caniwebview.com/features/web-feature-webgpu/ |
| Chrome Android, compatibility mode (OpenGL ES backend) | Behind a flag. | For devices without Vulkan. Not a default path. | https://developer.chrome.com/blog/new-in-webgpu-127 |

What this means for the engine: a large share of Android phones (Android 11 and older, Xclipse, other GPUs) and every iPhone below iOS 26 get WebGL. WGSL-only filters do not run there. The WebGL path needs either GLSL twins of the filters or a defined "filters off" look. That is an engine decision, not a platform-provider one.

## Recommendation

| capability | web provider does | reason |
|---|---|---|
| Haptics | `navigator.vibrate(ms)` when present. Before the first user gesture return `unavailable`. No API: `unsupported`. No switch trick. | Only Android has the API. The iOS trick is undocumented and can vanish. |
| Keep-awake | `navigator.wakeLock.request("screen")`. Hold the wish, re-acquire on `visibilitychange` to visible, release on `stop`. `NotAllowedError`: `denied`. Hidden: `unavailable`. | Supported on all four targets. The browser drops the lock on hide, so re-acquire is the provider's job. |
| Orientation lock | iOS: `unsupported`. Android: try `screen.orientation.lock`. Rejection: `unavailable`. Document that the game must be installed or fullscreen, and that manifest `orientation` is the real tool for an installed PWA. | iOS has no API. Android allows it only in fullscreen or installed. |
| Back | Do not map. Return `unsupported`. The game shows its own on-screen back control. | No sane web equivalent. History traps break the browser Back. `CloseWatcher` is Chromium only and not Baseline. In Tauri, Back comes from the native provider. |
| Lifecycle | Not in the provider. The engine keeps `visibilitychange` (already in `src/plugins/renderer/host/visibility.ts`). Optional later: `pageshow` with `persisted` to resume after a back-forward cache restore. | `visibilitychange` works on all targets. `freeze`/`resume` are Chromium only. |
| WebGPU | Not in the provider. The renderer keeps WebGPU first, WebGL fallback. | It is a renderer concern. The provider must not gate rendering. |
